# 1. Game Concept / 游戏概念

## 1.1 Elevator Pitch / 一句话电梯陈述

CityOfAnimals 是一款原创的移动端竖屏农场小镇经营游戏：玩家从地图上读懂每座建筑正在缺什么、产出什么和可交付到哪里，在共享库存的拉扯中决定先生产、先交付还是为更远目标留货，并把这些选择转化为一座持续变得更鲜活、更可读的小镇。

## 1.2 Core Fantasy / 核心幻想

**“我是这座动物小镇的规划者；每座建筑都在做事，而我一眼就知道该让哪一处先运转。”**

玩家不只是领取倒计时或清空订单，而是在一个可直接触摸的世界中安排物资去向：一份货物可以解决眼前需求、接上生产链、装入物流批次，或服务小镇成长。

## 1.3 Unique Hooks / 独特钩子

| 钩子 | 玩家感受 | 必须成立的产品规则 |
|---|---|---|
| 地图先于文字 | “我看建筑和图标就知道哪里可以推进。” | 核心行动必须由世界对象、轮廓、状态环、输入/产出图标和短标签共同传达；文字卡片不能替代世界。 |
| 共享库存带来真实取舍 | “现在交掉这批货，会拖慢另一个我想做的目标。” | 每个内容包复用已有材料，并让至少一项材料存在多个合法去向。 |
| 不同时间尺度的交付 | “短单、货运和小镇需求不是同一张订单换图标。” | 各交付渠道在准备方式、可见状态、回报作用和节奏上不同。 |
| 成长留在地图上 | “我完成的事改变了小镇，而不只是数字变大。” | 关键回报应开启建筑位、路线、功能空间或新需求，并能被玩家看见。 |

## 1.4 Game Pillars / 游戏支柱概览

| 支柱 | 定义 | 反支柱 | 设计测试 |
|---|---|---|---|
| P1 地图对象一眼可读 | 世界对象本身就是主要操作入口。 | 用文本列表承载城镇。 | 在 720 x 1280 截图中，能否辨认可收取、缺料、处理中、可交付的对象？ |
| P2 共享供应网产生取舍 | 生产不是孤立配方，而是有竞争关系的网络。 | 每件货只服务一条线。 | 玩家会不会为了一个目标暂缓另一个同样合理的目标？ |
| P3 交付去向具有层次 | 近、中、远及服务型目标有不同准备和回报。 | 同一订单面板仅换图标。 | 玩家能否说出为什么不把某批货立刻交掉？ |
| P4 可见建设回报循环 | 完成目标后，小镇的功能空间和下一轮选择扩大。 | 只涨数值而无世界变化。 | 一次关键结算后，玩家能否指出新出现的空间、路线或能力？ |

**支柱优先级：** P1 地图对象可读 > P2 共享供应网 > P3 交付层次 > P4 可见建设回报。任何新增装饰、货币或长等待都不能压过这四项。

## 1.5 Core Loop / 核心循环

`观察世界状态 → 选择下一条路线 → 生产/投入 → 收取并处理库存 → 选择本地/货运/空运/城镇服务去向 → 获得回报与可见成长 → 重新观察`

| 尺度 | 玩家要完成什么 | 核心体验 | 当前或计划承载 |
|---|---|---|---|
| 约 30 秒 | 点开一个对象，开始、完成或收取一次工作。 | 触摸后立刻理解因果。 | 农田、动物 shelter、工作坊和状态反馈。 |
| 约 5 分钟 | 准备并完成一个近端目标，或为下一条路线补齐缺口。 | “现在交”与“留货”的第一次权衡。 | F-003 本地委托；后续扩展为多对象准备。 |
| 单次会话 | 排查多个分区的瓶颈，为不同目标分配共享库存。 | 小镇在一次会话内从堵塞变得顺畅。 | F-004 后的农田、养殖、工坊分区；物流入口。 |
| 长期 | 解锁新建筑、交付渠道、功能空间与侧区。 | 新内容会反向改变旧货物的价值。 | F-005 至 F-009 的条件式内容阶梯。 |

**当前最小可玩链：** 场地 → 养殖材料 → 加工 → 本地交付。F-003 已具备行为证据，但仍不是已接受的视觉 MVP：须先完成干净的运行时截图验收。

## 1.6 MDA / 机制、动态与情感

| 层级 | CityOfAnimals 定义 |
|---|---|
| Mechanics / 机制 | 可点击世界对象、建筑状态机、原创生产输入输出、共享库存、交付目标、coins/renown、可见解锁与语言设置。 |
| Dynamics / 动态 | 缺料、满仓、准备进度和多去向让玩家反复重排优先级；新建筑为旧材料增加用途。 |
| Aesthetics / 情感 | 读懂、掌控、照料、筹划、建设成形，以及“这座小镇正在因我而运转”的满足。 |

## 1.7 Target Player Types / 目标玩家类型

| 玩家类型 | 需要得到什么 | 设计响应 |
|---|---|---|
| 轻度建设型玩家 | 短会话中也能看见一处地方被推进。 | 直接对象、短反馈、清晰下一步。 |
| 规划与优化型玩家 | 共享材料和多去向带来的可解释取舍。 | 可见缺口、库存反馈、差异化交付。 |
| 收集与长期成长型玩家 | 小镇从少量建筑逐步形成有连接的功能网络。 | 分区、可见扩张、旧内容获得新用途。 |

本计划不假定年龄、地域、市场规模或付费画像；这些需要经过制作人授权的研究和数据验证后再写入。

## 1.10 Risks / 风险

| 风险 | 早期信号 | 缓解与验收 |

# 2. Pitch Document / 产品 Pitch

## 2.1 Executive Summary / 执行摘要

CityOfAnimals 的产品机会在于把农场小镇品类中“生产、库存、交付、建设”的系统关系，转化为一款以直观世界对象为中心的原创移动端经营游戏。产品不依赖复刻任何既有作品的资产、数值或表现，而以可读地图、共享供应网、差异化交付和可见建设作为可验证的竞争方向。

当前风险管理优先于内容扩张：首条链 F-003 已实现但截图验收未关闭；只有在该行为与视觉门槛皆通过后，产品才按 F-004 至 F-010 的顺序拓展系统覆盖。

## 2.2 Game Overview / 游戏概览

| 项目 | 定义 |
|---|---|
| 类型 | 原创农场小镇经营与供应网络规划。 |
| 核心问题 | “我现在拥有的物资，应即时交付、投入下一座建筑，还是留给更远目标？” |
| 会话形态 | 短操作循环嵌入中等长度的供应整理与长期的分区建设。 |
| 体验承诺 | 每座可见建筑都传达状态、用途或下一步；每次关键交付都会让小镇的功能网络更丰富。 |
| 内容节奏 | 首条链 → 农场分区/Industry I → 轨道货运 → 城镇服务/Industry II → 空运 → 扩地 → 侧区 → 仅在验证后考虑长尾层。 |

## 2.4 Competitive Advantage / 差异化假设

这不是已验证的商业优势承诺，而是待原型验证的产品假设：

1. 以对象状态和地图片区替代“文字订单驱动”的默认入口，降低理解下一步的摩擦。
2. 以共享供应网和不同交付地平线制造可解释选择，而非通过叠加资源和等待制造规模感。
3. 以可见的建筑、路线和功能空间变化承接回报，让成长留在玩家的世界里。
4. 全部内容从原创名称、原创素材、原创数据与原创测试中形成，避免参考作品表达成为产品依赖。

# 3. Game Pillars / 游戏支柱详述

## 3.1 支柱总览

| 优先级 | 支柱 | 一句话定义 |
|---:|---|---|
| 1 | P1 地图对象一眼可读 | 建筑的形、状态和图标让玩家先于文字知道下一步。 |
| 2 | P2 共享供应网产生取舍 | 同一库存服务多个合理目标，玩家必须安排优先级。 |
| 3 | P3 交付去向具有层次 | 不同去向有不同的准备、节奏、状态和成长作用。 |
| 4 | P4 可见建设回报循环 | 关键回报改变可见空间、可用建筑或路线，让选择持续扩大。 |

## 3.2 每项支柱的深度定义

### P1 地图对象一眼可读

| 项目 | 定义 |
|---|---|
| 为什么重要 | 让玩家把注意力放在规划，而非寻找按钮或阅读长说明。 |
| 设计测试 | 在 720 x 1280 下，是否能区分可收取、缺料、处理中、满仓、可交付与锁定？ |
| 反支柱 | 以常驻文字订单栏或模态弹窗替代小镇本身。 |
| 系统映射 | 世界对象、建筑状态机、紧凑资源槽、上下文浮层、触控命中区、locale 短标签。 |
| 优先级 | P0；任何新增建筑先证明可读再谈装饰。 |

### P2 共享供应网产生取舍

| 项目 | 定义 |
|---|---|
| 为什么重要 | 供应关系让建筑“有理由共存”，并使玩家的选择有成本和意义。 |
| 设计测试 | 是否存在一项物资在两个以上合理目标间竞争，且选择一方会短暂延后另一方？ |
| 反支柱 | 新建筑只附带一条孤立配方，或依靠无限新增货币制造复杂度。 |
| 系统映射 | 原创配方表、库存、缺料提示、生产规则、交付需求和建设需求。 |
| 优先级 | P0；F-004 的产品验收重点。 |

### P3 交付去向具有层次

| 项目 | 定义 |
|---|---|
| 为什么重要 | 让“货物去哪里”成为核心决策，而非一键清空库存。 |
| 设计测试 | 本地、轨道、空运、城镇服务能否在准备方式、世界表现、状态链和回报作用上被区分？ |
| 反支柱 | 统一订单面板换皮；自动替玩家分配货物。 |
| 系统映射 | 本地委托、清单装载、手动发运、城镇需求、显式路线状态与结算反馈。 |
| 优先级 | P1；F-005 至 F-007 逐步验证。 |

### P4 可见建设回报循环

| 项目 | 定义 |
|---|---|
| 为什么重要 | 为重复生产提供持续目标，并使城市成长比纯数值提升更可信。 |
| 设计测试 | 完成关键目标后，能否看到新建筑位、可用路线、功能能力或新需求？ |
| 反支柱 | 奖励只增大抽象数值，地图和选择空间不变。 |
| 系统映射 | coins/renown、解锁条件、分区/地块、建筑位、物流站点、侧区。 |
| 优先级 | P1；F-005 后逐步形成，F-008 完整验证。 |

## 3.3 Anti-Pillars / 反支柱

1. **文本卡片小镇：** 地图只是背景，真正玩法藏在长列表和弹窗中。
2. **孤岛配方堆积：** 建筑数量增加但材料不复用、没有优先级冲突。
3. **换皮物流：** 交付渠道仅换视觉标识，状态和回报没有功能差异。
4. **数值/等待替代内容：** 依靠货币种类、强制等待或付费阻塞而不是可读的系统选择。
5. **外部表达依赖：** 用第三方名称、资产、轮廓、地图或界面结构作为实现模板。

## 3.4 Priority / 执行优先级

1. 在 F-003 截图验收前，只处理其现有验收门槛；不因本计划改变活动范围。
2. F-004 首先验证 P1 + P2：分区可读、对象可点、共享材料产生两条去向。
3. F-005 至 F-007 再验证 P3：每条物流/服务路线必须具备独立的完整可见状态链。
4. F-008 至 F-009 验证 P4：回报改变空间与供应网络，而非只增加数字。
5. F-010 必须等 solo 供应网达到内容密度后，由制作人重新做产品决策。

# 4. Player Journey / 玩家旅程

## 4.1 六阶段情感旅程

| 阶段 | 玩家目标与情绪 | 核心体验 | 留存钩子（设计意图，非数据结论） | 主要流失点与防线 |
|---|---|---|---|---|
| 1. 发现与引导 | “这是什么地方？我能做什么？”从好奇到读懂。 | 直接点一个田地/建筑，看到输入、状态、产出与下一步。 | 第一处对象马上有因果反馈，并显示世界不是静态背景。 | 若第一分钟只能读文字或点按无反应则流失；以 P1 的对象状态和触控验收防线解决。 |
| 2. 早期成长 | “我能让这条小链运转。”从完成感到第一次规划。 | F-003 的生产—收取—本地交付，并首次看到共享材料的价值。 | 完成一条链后留下一个可理解的下一步目标。 | 若完成后没有下一选择或阻塞无说明则流失；需清晰缺料/满仓反馈。 |
| 3. 核心体验 | “我的分区彼此有关。”从掌握到取舍。 | F-004 的农田、养殖、工坊并列，玩家分配同一库存。 | 两个合理目标同时出现，让玩家形成自己的准备顺序。 | 若所有步骤变成唯一点击顺序则流失；必须证明双去向机会成本。 |
| 4. 深度投入 | “我为远目标提前安排。”从计划到期待。 | F-005 货运、F-006 城镇服务：不同目标消耗不同组合并改变建设方向。 | 可见装载/完成过程和新需求让下一次会话有准备理由。 | 若物流只是一张更大的订单表则流失；每种渠道须有不同状态链。 |
| 5. 精通与社交准备 | “我知道怎样让小镇更顺畅。”从优化到表达。 | F-007 空运、F-008 扩地、F-009 侧区让旧材料与新区域交叉。 | 新空间和新路线让玩家可表达自己的优先级。 | 若扩张只加摆设或没有重用旧物资则流失；以功能空间和关系复用验收。 |
| 6. 长期留存 | “我仍有想完善和想共同完成的事。”从稳定习惯到长期目标。 | 只有在单人循环内容密度足够后，才评估收藏与合作层。 | 长尾目标须扩展已有循环，而不是强制替代它。 | 过早加入社交/活动会掩盖单人内容不足；F-010 仍需独立产品决策。 |

## 4.2 Retention Hooks / 留存钩子设计清单

| 钩子 | 触发时点 | 它强化的支柱 | 验证方式 |
|---|---|---|---|
| 可读的“下一处” | 每次回到主地图 | P1 | 截图/试玩中可指出下一可推进对象。 |
| 缺口可解释 | 缺料、处理中、满仓、未解锁时 | P1、P2 | 玩家能说出阻塞原因及下一步，而不是反复盲点。 |
| 共享物资的取舍 | 两个需求同时出现时 | P2 | 玩家会主动保留或转移一批物资。 |
| 交付前的准备 | 货运、空运和服务目标出现时 | P3 | 交付过程有可见进度与不同决策，不自动代替玩家选择。 |
| 地图的功能变化 | 关键结算/解锁后 | P4 | 世界上出现可见的新空间、对象或路线。 |

这些是待验证的设计钩子，不等同于已经证明的留存率、回访率或商业指标。指标定义、埋点和数据阈值必须在获批的数据工作包中建立。

## 4.3 Churn Points / 关键流失点与处置

| 流失点 | 可能原因 | 处置规则 | 所属门槛 |
|---|---|---|---|
| 首次进入看不懂 | 图标、状态和触控区域不清楚。 | 世界对象优先；短标签只作补充；验证 720 x 1280。 | F-003/F-004 视觉与行为验收。 |
| 生产结束没有意义 | 产出只有一次性领取，未接入需求。 | 每项产出都应有至少一个当前或已知未来去向。 | 所有功能说明。 |
| 库存像惩罚 | 满仓/缺料只阻止玩家，没有恢复路径。 | 给出原因、相关对象和可恢复的下一步；不得用支付作为默认解除。 | 状态机与 QA。 |
| 交付渠道无法区分 | 玩家感受只是同一订单的不同皮肤。 | 为每条渠道定义独立准备、加载、出发/服务、结算与回报作用。 | F-005 至 F-007。 |
| 内容变多却不连通 | 新建筑/侧区未复用旧供应网。 | 新内容必须给既有材料或建筑增加至少一个新关系。 | F-004 至 F-009。 |
| 验收被跳过 | 未获得清晰截图或行为证据就继续开发。 | 当前先关闭 F-003 截图门槛；后续功能逐项设来源、写入授权和回执。 | 工作流控制面。 |
