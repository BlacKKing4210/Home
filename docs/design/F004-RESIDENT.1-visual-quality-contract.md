## 1. 一句话视觉方向

**清爽而有生活密度的手绘动物小镇：道路像血管一样把住房、农田、工坊和装卸点连起来，动物居民的行走、劳动与回家让每座建筑显得真正被使用。**

## 2. 玩家记忆点

玩家看见一名动物居民从自己的住房出门，沿着亲手铺设的道路走到田地或工坊完成工作，再把产出送到等待的订单车；车辆装满后鸣笛离开，小镇因此获得下一次建设资源。

## 3. 视觉原则

1. **先读空间，再读装饰。** 1×1 网格、道路、建筑底座、入口和作业点在 50% 显示下仍清楚。
2. **先读居民，再读气泡。** 能用走路、停留、工具和货物表达的状态，不增加文字或常驻按钮。
3. **正式资产进入主页面。** 道路、田地、住房、代表建筑、车辆和居民必须是原创、批准、可追溯资产；emoji、字母块、灰框和未批准占位图只可用于 dev-only 机械测试。
4. **统一形状语言。** 软菱形地块、厚实圆角建筑体块、清晰深色轮廓、低饱和地面与高可读交互色。
5. **生活密度不等于图标密度。** 用居民、货物、烟、门窗、作业动作和车辆创造活力，限制状态气泡数量。
6. **项目身份优先。** 不套用 Zhanchengdashi 的 1930s 海报 UI，不照搬 Fisher 页面，也不复制 Township、Hay Day、Animal Crossing 的角色、建筑、地图、UI、色板或商业身份。

## 4. 形状职责

| 类别 | 形状职责 |
|---|---|
| 网格/田地 | 45° 菱形；1×1 是最小逻辑和视觉单位；相邻地块可形成连续土壤边界，但碰撞与状态仍独立。 |
| 道路 | 1×1 网格段；直线、弯角、丁字、十字与终点必须有清楚连接；边缘不侵入建筑底座。 |
| 建筑 | 以批准占地为底座，主要体块不越过底座的前左右可读边界；屋檐可有限外扩但不改变占地。 |
| 居民 | 头身比例与轮廓保证 64–96 px 显示仍能识别；通勤、工作、搬运、休息姿态可区分。 |
| 车辆 | 有明确车头方向、货箱容量与装载变化；不得只是订单卡外壳。 |
| 状态标记 | 只显示第一阻塞或关键完成；使用图形 + 轮廓/材质双重线索。 |

## 6. 材质与光影

- 地面：低频、轻手绘颗粒，不使用重复明显的大箭头纹理。
- 道路：软边泥土/碎石层次，车辙只在车辆路径出现，避免铺满装饰。
- 田地：土壤沟槽与边界可读；不同生长状态改变作物而非改变格子尺寸。
- 建筑：木、石、陶瓦和布篷形成易读材料区；同类建筑共享材料语言但用轮廓和功能部件区分。
- 光线：柔和日间主光；统一左上或右上受光方向；所有世界实体有稳定接触阴影。
- 遮挡：居民被前景建筑遮住超过身体 40% 时，屋顶/前墙局部淡化或显示角色轮廓；不让角色消失。
- HUD：使用简单、温暖、原生 Godot 的面板与动态文字；承载面独立于复杂世界背景。

## 8. 动效职责

| 行为 | 常规表现 | reduced-motion |
|---|---|---|
| 走路 | 轻微上下步态 + 方向倾斜；沿导航路径平滑移动 | 无弹跳，只保留位置和朝向 |
| 到达岗位 | 短停、看向作业点、工具/姿态切换 | 姿态瞬时切换 |
| 工作 | 2–4 个程序化姿态阶段；田地/建筑同步响应 | 静态工作姿态 + 进度 |
| 搬运 | 货物作为独立视觉子节点出现并随居民移动 | 保留货物位置变化 |
| 阻塞 | 居民停在安全点，短暂摇头/回望，路径或对象轮廓提示 | 静态姿态 + 阻塞标记 |
| 车辆到达 | 减速、车轮/扬尘、停靠 | 匀速滑入或直接停靠淡入 |
| 装载 | 世界内货物进入货箱，货箱填充可见 | 分段填充 |
| 离场 | 发动、鸣笛、短镜头焦点、车辙 | 无镜头冲击，车辆平滑离开 |
| 建造完成 | 居民停工退开，建筑从施工态过渡到正式态 | 状态替换 + 轮廓确认 |

程序化动作只作用于视觉子节点，必须可中断、可重置、离树清理，并受 reduced-motion 偏好控制。

## 9. 声音职责

声音尚未进入资产制作，本合同只规定职责：

- 居民脚步：低频、材质相关、限制并发。
- 作业：按田地/木工/动物照料/加工区分短循环，镜头外衰减。
- 阻塞：一次短提示，不持续报警。
- 车辆：远处进入、停车、装载、完成鸣笛和离场五段；完成鸣笛是交付记忆点。
- 建造/邀请：温暖短确认，不使用参考商业游戏音频。
- 无合规音源时保持静音，视觉必须独立可读。

## 11. 安全区、触控与可读性

- 基准：720×1280 竖屏；等比缩放并居中。
- 顶部/底部安全区由运行设备传入；任何关键 CTA 不贴边。
- 最小触控区 52×52 px；相邻动作间隔至少 8 px。
- 同屏突出状态标记不超过 4 个。
- 居民在 50% 预览下仍能区分通勤、工作和阻塞。
- 建筑入口与道路连接在无文字、无颜色条件下仍能读出。
- zh-CN / en 均验证标题、状态、数值、空态与错误文本不溢出。

## 12. 性能预算

代表性切片目标：

- Windows GL Compatibility，720×1280：目标 60 FPS，验收底线稳定 30 FPS。
- 移动居民：首切片 1 名，预算设计扩展到同屏 12 名；每名只保留一个活动路径和有限视觉子节点。
- 可见车辆：1；装载货物视觉实例不超过订单需求品类数。
- 同屏活动程序化反馈：最多 6 组；粒子/扬尘自动池化并限制寿命。
- 静态道路优先使用 TileMap/合批；建筑资源进入图集前必须通过占地与锚点一致性检查。
- 不允许无限 Tween、无限节点、每帧重建全图导航或对每个居民执行全地图搜索。
- 导航图只在道路/建筑占地发生变化时增量更新；日常工作复用路径结果或局部重算。

## 13. 原创与反复制

- 不复制 Township、Hay Day、Animal Crossing 或其他商业游戏的角色、动物比例、建筑轮廓、地图布局、UI、图标、货币、配方、文案、数值、动效时序、音频或品牌元素。
- 不把参考画面当成生成提示词的直接风格锚；只提取“居民可见地工作”“道路连通”“车辆交付”“建筑状态直观”等抽象方法。
- `zhanchengdashi` 只复用用户自有的程序化运动方法与可验证内部资源路径；不复用战斗动作语义或 1930s 页面身份。
- 每项正式资产保留来源、版本、用途、哈希、占地、锚点、作业点和批准状态。
- 未批准候选与 `NOT_RUNTIME` 资源不得进入玩家可见验收路径。
