# PD-002 动物居民小镇产品方向重基线

**决策状态：** `APPROVED FOR DESIGN REBASELINE`  
**决策日期：** 2026-07-25  
**决策版本：** `PRODUCT-REBASELINE.1`  
**制作人：** Codex `/root`  
**运行时权限：** `false`

## 正式决策

CityOfAnimals 从“玩家逐个点击田地、动物栏、机器与收取位的生产农场”重基线为：

> 玩家规划一座真正有动物居民生活和工作的慢节奏小镇。玩家负责建造、邀请、派遣与长期调整；动物居民沿道路走到建筑，亲自执行种田、照料、加工、装载与生活行为，让小镇在玩家可见的世界内持续运转。

## 单一玩家记忆点

**动物不是按钮或加成，而是玩家看得见、会走路、会生活、会把小镇运转起来的居民。**

## 设计判断

1. 这不是在旧生产循环外增加“工人加成”，而是把日常生产动作的执行权从玩家手指移交给动物居民。
2. 玩家主要决策从“现在点哪个生产按钮”变为“建什么、住进谁、谁去哪里工作、道路是否顺畅、长期供给如何安排”。
3. 订单不再主要由列表解释，而由世界内车辆的到达、等待、装载与离场表达。
4. 空间秩序优先于建筑美术尺寸：先确定逻辑网格、占地目录、道路/入口/作业点，再决定哪些建筑资源复用、改造或重做。
5. 主页面不靠更多常驻按钮、菜单和文字制造内容；尽量用居民、建筑、道路、车辆、货物和状态动作直接表达。
6. 参考《动物森友会》只提炼慢节奏、居民存在感、邀请与生活感；参考农场经营品类只提炼生产网络、建筑可读性和交付节奏。禁止复制任何商业角色、UI、布局、数值、文案、建筑、地图或艺术身份。

## 推荐产品方案

### 玩家节奏

- 低频：建造、邀请居民、分配岗位、调整道路、改变工作优先级、选择订单承诺。
- 自动：居民出门、寻路、排队、工作、产出、把货物送入可用存储/装载点、休息和返回生活。
- 观察：玩家通过地图上的人物、道路流量、建筑动画、货物移动与车辆状态理解小镇。
- 介入：只有出现缺路、缺料、满仓、岗位拥堵或优先级冲突时，玩家才需要调整。

### 代表性闭环

`建造居民住房 → 邀请一名动物 → 动物入住 → 铺设住房到田地/代表建筑的道路 → 派遣岗位 → 动物沿路到达并作业 → 产出满足一张订单 → 订单车装载并离开 → 获得资源 → 规划下一处住房或生产设施`

该闭环必须一次证明五件事：

1. 空间占地和道路有秩序；
2. 动物是居民而非按钮；
3. 玩家操作频率降低；
4. 订单在世界内发生；
5. 主页面达到正式 2D 卡通视觉质量。

## 旧规则处置

| 旧规则/资产 | 处置 | 新解释 |
|---|---|---|
| 45° 大地图、720×1280、可建设很多建筑 | 保留 | 逻辑直角网格，以 45° 等距方式绘制；空间容量由统一占地目录管理。 |
| `zh-CN` 首启、设置中可选 `en` | 保留 | 所有居民、岗位、建筑、车辆和失败反馈继续使用 locale key。 |
| 共享库存、配方网络、仓储阻塞 | 保留并重构 | 作为居民工作系统的输入/输出约束；不要求玩家逐次点击启动和收取。 |
| F003/F004 物品与建筑 ID | 迁移输入 | 经过占地、作业点、视觉质量和新状态机审核后决定复用/改造/废弃。 |
| 玩家直接播种、收获、喂养、开始机器、点击成品收取 | 删除为默认主循环 | 由已派遣居民在资源和道路条件满足时自动执行；玩家只调整岗位与优先级。 |
| 委托板/订单卡作为主要表达 | 合并到车辆订单 | 订单信息可在选中车辆时显示，常态以车辆和装载物表达。 |
| F004 分区营建板 | 降级/待重审 | 如保留，只用于长期规划，不承担日常生产操作或成为常驻主菜单。 |
| F004 固定功能位 | 取消为默认 | 改为网格合法放置；仅剧情/地标可使用固定位置。 |
| 手动收取是普遍契约 | 删除 | 常规产出由居民搬运；仓储满或装载点阻塞才保留世界内待处理状态。 |
| F003-VQ.1 收获飞入 HUD | 保留为历史反馈方法 | 新方向优先显示居民搬运和车辆装载；HUD 飞行只作短反馈，不替代世界因果。 |
| 临时 UI、字母块、占位图可进入主页面评审 | 局部覆盖为禁止 | 模拟经营主页面玩家可见评审、截图和运行验收只接受正式/批准资产。 |

- **版本：** `F004-RESIDENT.1`
- **名称：** `动物居民小镇：空间秩序与自主作业基础`
- **旧版本关系：** `F004-DISTRICT.1 -> REVISE_REQUIRED / SUPERSEDED_BY F004-RESIDENT.1`
- **依赖：** F003 只作为旧方向可玩基线、资产和技术来源
- **下游：** F005 铁路货运必须改为建立在车辆装载、道路网络和居民搬运之上
- **当前阶段：** `DESIGN_REBASELINE_REVIEW`
- **运行时权限：** `false`

不新建 F011。F004 是矩阵中最高优先级且尚未进入运行时的功能；直接重建其版本关系最能保持路线清晰，也避免旧 F004 与新基础并行争夺同一产品位置。

## 少数待确认事项

以下不阻塞本次设计评审，均已给出推荐默认值：

1. **岗位控制粒度：** 推荐“一名居民同一工作时段只有一个主岗位”，不做 RTS 式连续点选移动。
2. **离线推进：** 推荐离线只结算已排定、路径已验证、输入已保留的工作块；玩家回到游戏后先表现一次有限的返场/交付，不让居民在镜头前瞬移。
3. **订单超时：** 推荐 MVP 无硬失败倒计时；玩家可主动谢绝，车辆空驶离开并在稍后刷新，保持慢节奏。

只有用户明确反对以上推荐时才改向；其余细节由制作人在正式设计和后续代表性切片中继续收敛。
